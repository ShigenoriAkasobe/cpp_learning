# テンプレート（Templates）ノート

このレッスンでは、同じ処理を複数の型で使い回すための**テンプレート**を学びます。
実際に動くコードは [main.cpp](main.cpp) にあります。

## テンプレートとは

テンプレートは、型を後から決める「コードのひな形」です。
整数用、浮動小数点数用というように、型ごとに同じ関数を書く代わりに、型に依存しない処理を一度だけ定義できます。

```cpp
template <typename T>
T add(T a, T b) {
    return a + b;
}
```

この関数の`T`は、具体的な型の代わりに置かれた名前です。
呼び出し時の引数から`T`が決まり、必要な型の関数がコンパイラによって生成されます。

```cpp
add(10, 20);   // Tはint
add(1.5, 2.5); // Tはdouble
```

イメージとしては、次の2つの関数を手作業で書く代わりに、1つのテンプレートから作るということです。

```cpp
int add(int a, int b);
double add(double a, double b);
```

テンプレートは実行時に型を調べる仕組みではなく、**コンパイル時に型を決めてコードを生成する仕組み**です。
そのため、静的型付けの安全性を保ちながら、型ごとの重複を減らせます。

## 関数テンプレート

### 基本形

```cpp
template <typename T>
T add(T a, T b) {
    return a + b;
}
```

各部分の意味は次のとおりです。

- `template <typename T>`: これからテンプレートを定義する。`T`は型パラメータ
- 最初の`T`: 戻り値の型
- `T a`, `T b`: 2つの引数の型
- `a + b`: `T`に`+`演算子が存在することを前提にした処理

`typename`の代わりに`class`と書くこともできます。

```cpp
template <class T>
T add(T a, T b) {
    return a + b;
}
```

この場所では`typename`と`class`の意味に違いはありません。型パラメータであることを表しています。

### 値渡しと参照

関数の引数を`T`で受け取るか、`const T&`で受け取るかによって、値の受け取り方が変わります。

```cpp
template <typename T>
T print_twice(T value) {
    std::cout << value << " " << value << std::endl;
    return value;
}

template <typename T>
T print_twice2(const T& value) {
    std::cout << value << " " << value << std::endl;
    return value;
}
```

`T value`は**値渡し**です。呼び出し側の値をもとに、関数の中に別の`value`が作られます。
そのため、`std::string`のような大きなオブジェクトを左辺値で渡すと、引数を作るためのコピーが発生します。
関数の中で`value`を変更しても、呼び出し側の元の値は変わりません。

`const T& value`は、`T`型の値を**読み取り専用の参照**で受け取ります。
引数を作るためのコピーを避けられますが、`const`が付いているため、関数の中から`value`を変更できません。

```cpp
std::string message = "Hello";
print_twice(message);  // 値渡し。引数のコピーが作られる
print_twice2(message); // const参照。引数のコピーを作らない
```

`int`のように小さな型ではコピーのコストが小さいため、違いを実感しにくいことがあります。
一方、`std::string`や`std::vector`のような大きな型では、`const T&`によって不要なコピーを避けられます。

戻り値に`T`を書く場合と`const T&`を書く場合にも違いがあります。

```cpp
T get_value() const;        // 値をコピーして返す
const T& get_reference() const; // 元の値への読み取り専用参照を返す
```

`T`を返す場合は、呼び出し側が独立した値を受け取るため、元のオブジェクトの寿命を気にする必要がありません。
`const T&`を返す場合はコピーを避けられますが、参照先のオブジェクトが破棄された後に使ってはいけません。
`PairBox`の`first()`や`second()`は、`PairBox`が保持している値を読み取るための関数なので、`const T&`を返す設計にできます。

### 型推論と明示的な指定

通常は引数から型が推論されるので、`<int>`などを省略できます。

```cpp
std::cout << add(10, 20) << std::endl;     // intとして呼び出す
std::cout << add(1.5, 2.5) << std::endl;   // doubleとして呼び出す
```

型を明示したい場合は、関数名の後ろに型を指定します。

```cpp
std::cout << add<double>(1, 2.5) << std::endl;
```

この場合、`T`を`double`に固定してから、`1`を`double`へ変換して渡します。

### 型が一致しない場合

`add`は2つの引数に同じ`T`を使う定義です。そのため、次の呼び出しでは型推論が決まりません。

```cpp
// add(1, 2.5); // intとdoubleから同じTを推論できない
```

このような場合は、型を明示できます。

```cpp
add<double>(1, 2.5); // Tをdoubleに固定
```

テンプレートは「何でも自動的に処理する」仕組みではありません。
使用する型が、関数本体で必要な演算やメンバ関数を提供している必要があります。

### 文字列を扱うときの注意

次のコードは、そのままでは使えません。

```cpp
// add("Hello", "World");
```

文字列リテラルは`std::string`ではなく、配列から変換された`const char*`として扱われます。
`const char*`同士には、文字列連結を意味する`+`演算子がありません。
文字列として加算したい場合は、`std::string`を使います。

```cpp
add(std::string{"Hello"}, std::string{"World"});
```

テンプレートでは、型だけでなく「その型がどの操作をサポートしているか」も重要になります。

## クラステンプレート

関数だけでなく、クラスもテンプレートにできます。

```cpp
template <typename T>
class Box {
private:
    T value;

public:
    Box(T v) : value(v) {}

    T get() const { return value; }
    void set(T v) { value = v; }
};
```

`Box`は、内部に`T`型の値を1つ持つクラスです。
使うときに`T`を指定します。

```cpp
Box<int> intBox(123);
Box<std::string> strBox("Hello Template");
```

この2つは、どちらも同じテンプレートから作られますが、別の型です。

- `Box<int>`: `int`を保持する箱
- `Box<std::string>`: `std::string`を保持する箱

```cpp
std::cout << intBox.get() << std::endl;
intBox.set(456);

std::cout << strBox.get() << std::endl;
strBox.set("New value");
```

`Box<int>`に文字列を入れたり、`Box<std::string>`に整数を入れたりはできません。
型の違いはコンパイル時に検査されます。

### `const`メンバ関数との組み合わせ

```cpp
T get() const { return value; }
```

最後の`const`は、「`get()`は`Box`の状態を変更しない」という意味です。
テンプレートであっても、通常のクラスと同じように読み取り用のメンバ関数へ`const`を付けます。

## コンセプト（C++20）

テンプレートでは、関数本体の中で使った演算が型に存在しないと、分かりにくいコンパイルエラーになることがあります。
C++20の**コンセプト**を使うと、テンプレート引数に必要な条件を先に表現できます。

```cpp
template <typename T>
concept Addable = requires(T a, T b) {
    { a + b } -> std::convertible_to<T>;
};
```

この`Addable`は、次の条件を表しています。

1. `T`型の値`a`と`b`を用意できる
2. `a + b`という式が書ける
3. 加算結果を`T`へ変換できる

`requires`の中身は実行される処理ではありません。
型が条件を満たすかをコンパイル時に確認するための記述です。

### コンセプトを使った関数

```cpp
template <Addable T>
T safe_add(T a, T b) {
    return a + b;
}
```

`template <Addable T>`は、「`T`は`Addable`の条件を満たさなければならない」と宣言しています。
そのため、加算できない型で呼び出すと、条件に合わないことがエラーの理由として示されやすくなります。

同じ制約は、次のようにも書けます。

```cpp
template <typename T>
    requires Addable<T>
T safe_add(T a, T b) {
    return a + b;
}
```

短い書き方の`template <Addable T>`を使うか、`requires`を使うかは、制約の複雑さやチームの書き方に合わせます。

### `Addable`を満たさない例

```cpp
// safe_add((void*)0, (void*)0);
```

`void*`同士には加算が定義されていないため、`Addable`の条件を満たしません。
この呼び出しはコンパイルエラーになります。

コンセプトを使うと、単に「テンプレートの内部でエラーになった」と考えるのではなく、
「この関数は加算可能な型だけを受け付ける」とインターフェースで表現できます。

## C言語・Pythonとの比較

### C言語との違い

C言語では、同じ処理を型ごとに関数として用意することがよくあります。

```c
int add_int(int a, int b);
double add_double(double a, double b);
```

C++の関数テンプレートなら、型に依存しない処理を一つの定義にまとめられます。

```cpp
template <typename T>
T add(T a, T b) {
    return a + b;
}
```

ただし、テンプレートは型を隠してしまう機能ではありません。
どの型で使うかはコンパイル時に決まり、使えない操作があればコンパイルエラーになります。

### Pythonとの違い

Pythonも同じ関数を複数の型で呼び出せますが、確認されるタイミングが異なります。

- Python: 実行時に値の型を確認し、実行した場所でエラーになる
- C++テンプレート: コンパイル時に型を決め、実行前にエラーを検出する

テンプレートはPythonのように「同じコードを型を問わず使う」という面があります。
一方で、C++ではコンパイル時の型検査と、型に応じた最適化を受けられます。

## テンプレートを使うときの考え方

テンプレートを書く前に、次の順番で考えると整理しやすくなります。

1. 型だけが違う同じ処理が複数存在するか
2. その処理に必要な操作は何か
3. 必要な操作をコンセプトで表現できるか
4. テンプレートにしたことで、コードが読みやすくなっているか

「何でも受け付けるテンプレート」を作るより、必要な条件を明確にしたテンプレートのほうが保守しやすくなります。

## よくあるつまずき

### コンパイルエラーが関数の中で大量に出る

テンプレート引数が必要な操作を提供しているか確認します。
加算、比較、コピー、メンバ関数の呼び出しなど、テンプレート本体で使っている操作が原因になります。

C++20では、コンセプトや`requires`で条件を明示すると、エラーの内容を整理しやすくなります。

### テンプレートの定義を`.cpp`に分けたらリンクエラーになる

テンプレートは、使われる型に応じたコードをコンパイル時に生成します。
そのため、通常はテンプレートの定義をヘッダーファイルや、呼び出し側から見える場所に置きます。
大きなプロジェクトでは、テンプレートの宣言と定義を`.hpp`にまとめる形がよく使われます。

### 型パラメータを増やしすぎる

テンプレート引数が増えると、使い方やエラーメッセージが複雑になります。
まずは`add`や`Box`のような小さな例で、型を一般化するメリットが本当にあるか確認します。

## まとめ

| 用語 | 役割 |
| --- | --- |
| 関数テンプレート | 型に依存しない関数を定義する |
| クラステンプレート | 型に依存しないクラスを定義する |
| `typename T` | 型パラメータを宣言する |
| 型推論 | 引数や指定からテンプレート引数を決める |
| コンセプト | テンプレート引数が満たす条件を表す |
| `requires` | 型や式の条件をコンパイル時に確認する |

テンプレートは、C++の標準ライブラリを理解するための重要な基礎です。
`std::vector<T>`や`std::unique_ptr<T>`も、型をパラメータとして受け取るクラステンプレートです。
