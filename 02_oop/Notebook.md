# オブジェクト指向 (OOP) 学習ノート

## Q&A: 基底クラスのポインタで派生クラスを扱う理由

### Q. `Animal* myPet = new Cat("Tama");` は何をしているのか？ `Cat cat("Tama");` との違いは？

### A. 多態性（ポリモーフィズム）を実現するための重要な書き方です。

この 1 行では以下の 3 つが行われています。
1.  `new Cat(...)`: ヒープ領域に `Cat` オブジェクトを作成。
2.  `Animal*`: 基底クラスのポインタ変数を宣言。
3.  代入: `Cat` は `Animal` の一種なので、親のポインタ型に代入可能（アップキャスト）。

#### 違いの比較

| 書き方 | `Cat cat("Tama");` | `Animal* p = new Cat("Tama");` |
| :--- | :--- | :--- |
| **場所** | スタック (自動変数) | ヒープ (動的確保) |
| **寿命** | スコープを抜けると自動消滅 | `delete` するまで残る |
| **目的** | 単にそのクラスを使いたい時 | **複数の異なるクラスを統一的に扱いたい時** |

#### なぜこの書き方が必要なのか？

例えば、犬 (`Dog`) と猫 (`Cat`) をまとめて管理したい場合、型が違うためそのままでは同じリストに入れられません。
しかし、「動物 (`Animal`)」として扱えば、同じリストに入れてループ処理などが可能になります。

**C++ の例:**
```cpp
std::vector<Animal*> zoo;
zoo.push_back(new Cat("Tama"));
zoo.push_back(new Dog("Pochi"));

for (Animal* a : zoo) {
    a->speak(); // 中身に応じて "Meow!" や "Woof!" と鳴く (多態性)
}
```

**Python との比較:**
Python は変数が型を持たないため `[Cat(), Dog()]` と書けますが、C++ は型に厳格なため、**「共通の親クラスのポインタ」** を使うことでこれを実現します。

## Q&A: `push_back` の役割

### Q. `push_back` は Python の `append` と同じ？

### A. 基本的な役割は同じですが、「型」と「コピー」に注意が必要です。

| 特徴 | Python (`list.append`) | C++ (`std::vector::push_back`) |
| :--- | :--- | :--- |
| **追加できるもの** | 何でも OK | **宣言した型のみ** (例: `int` のみ、`Animal*` のみ) |
| **データの扱い** | 参照を追加 | **コピー**を作成して保存 (ポインタならアドレスのコピー) |

**注意点:**
`std::vector<Dog> dogs;` に `dogs.push_back(myDog);` すると、`myDog` の**コピー（複製）**がリストに入ります。元の `myDog` とは別物になる点に注意が必要です。
ポインタのベクタ (`std::vector<Animal*>`) の場合は、アドレスがコピーされるだけなので、Python の感覚に近くなります。

## Q&A: `new` の役割

### Q. `new` はどういう役割？

### A. 「動的メモリ確保」を行う演算子です。

1.  **メモリ確保**: ヒープ領域からメモリを確保する。
2.  **初期化**: コンストラクタを呼び出す。
3.  **ポインタ返却**: 確保した場所のアドレスを返す。

**なぜ必要なのか？**
*   **スタック変数 (`Dog d;`)**: スコープ `{}` を抜けると勝手に消える。
*   **ヒープ変数 (`new Dog;`)**: `delete` するまで**消えずに残る**。

関数をまたいでデータを持ち越したり、リストで管理したりする場合に必須となります。
(※ 現代 C++ では生の `new` ではなく、スマートポインタを使うのが一般的です。次は `03_memory` でそれを学びます)
